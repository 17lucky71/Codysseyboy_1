# 🤖 [프로젝트 2] AI 연동 자동화 파이프라인 설계서
 
## 📋 개요
 
**반복 업무 정의:**
매일 팀 공용 메일함으로 들어오는 고객 문의 이메일을 사람이 직접 읽고, 문의 유형을 분류하고, 내용을 요약해서 스프레드시트에 기록한 뒤 긴급 건은 팀 채널에 따로 알리는 작업을 반복하고 있었다. 이 과정을 자동화하기 위해 이메일 수신 → AI 분석(분류/요약/긴급도 판단) → 조건 분기 → 기록/알림으로 이어지는 파이프라인을 설계했다.
 
---
 
## 1. 도구 선정
 
### 1.1 선정 도구: **Make**
 
### 1.2 선정 이유
 
| 고려 항목 | 판단 근거 |
|---|---|
| 조건 분기 복잡도 | Router는 분기 수 제한이 없어 향후 유형별(기술지원/결제/계약 등) 세분화 확장이 쉬움 |
| 비용 | 무료 플랜(월 1,000 Ops)만으로 테스트 및 소규모 운영 가능. Zapier 무료 플랜은 2-Step 제한이라 AI 분석 + 분기 + 다중 액션 구조를 무료로 구현하기 어려움 |
| 응답 속도 | Webhook 기반이라 이메일 수신 후 처리까지 지연이 짧음(약 5초) |
| 데이터 흐름 확인 | 각 모듈의 입출력 데이터를 시각적으로 바로 확인할 수 있어 AI 응답(JSON) 파싱 디버깅이 수월함 |
 
Zapier는 초보자 친화적이고 앱 통합 수가 많다는 장점이 있으나, 본 파이프라인처럼 **AI 액션 + 조건 분기 + 다중 후속 액션**이 결합된 구조에서는 무료 플랜 제약과 폴링 지연(2~3분)이 실질적인 단점으로 작용해 제외했다.

## 2. 워크플로우 설계
 
### 2.1 전체 구조도
 
```
[Trigger] Gmail - Watch Emails (INBOX)
        ↓
[Module 1] OpenAI - Create a Completion (gpt-4o)
   → 이메일 제목+본문을 입력받아 JSON으로 분석 결과 반환
        ↓
[Module 2] Parse JSON
   → type(문의유형) / summary(요약) / urgency(긴급도) 추출
        ↓
[Module 3] Router (조건 분기)
   ├─ Route A: urgency = "High"
   │     ├─ Google Sheets - Add a Row (전체 이력 기록)
   │     └─ Discord - Send a Message (긴급 알림)
   │
   └─ Route B: urgency = "Low" (Default)
         └─ Google Sheets - Add a Row (전체 이력 기록만)
```
 
### 2.2 단계별 설명
 
1. **Trigger (Gmail)** — 팀 공용 메일함(INBOX)에 새 이메일이 도착하면 워크플로우가 시작된다.
2. **AI 분석 (OpenAI)** — 이메일 제목과 본문을 GPT-4o에 전달해 문의유형, 3줄 요약, 긴급도(High/Low)를 JSON 형식으로 반환받는다. Temperature를 0.3으로 낮게 설정해 분류 결과의 일관성을 높였다.
3. **JSON 파싱** — AI 응답 텍스트를 구조화된 필드(type/summary/urgency)로 변환해 이후 모듈에서 바로 참조할 수 있게 한다.
4. **조건 분기 (Router)** — 긴급도가 High인 경우와 Low인 경우로 경로를 나눈다.
5. **기록/알림** — 모든 이메일은 Google Sheets에 이력으로 남기되, High 등급만 Discord로 즉시 알림을 보내 팀이 우선순위를 놓치지 않도록 한다.
### 2.3 AI 프롬프트 설계 이유
 
시스템 프롬프트에서 응답 형식을 JSON으로 엄격히 제한한 이유는, 이후 Make의 Parse JSON 모듈에서 안정적으로 필드를 추출하기 위함이다. 긴급도 판단 기준(서비스 장애·결제 오류·클레임 → High / 일반 문의·정보 요청 → Low)을 프롬프트에 명시해 분류 근거를 사람이 검증할 수 있게 했다.
 
---
 
## 3. 예외 처리 및 향후 확장 (참고)
 
- AI 응답이 JSON 형식을 벗어나는 경우를 대비해 Parse JSON 모듈 실패 시 기본값(urgency=Low)으로 처리하는 방안을 고려할 수 있다.
- 현재는 High/Low 2단계 분기이나, 향후 문의유형(type) 기준으로 Router 경로를 추가해 담당 부서별 알림 채널로 세분화할 수 있다.
