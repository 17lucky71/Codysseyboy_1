# 🤖 [프로젝트 2] AI 연동 자동 분류 및 디스코드 알림 파이프라인 상세 설계서

## 1. 반복 업무 정의 및 자동화 도입 목적
* **대상 반복 업무:** 매일 수십 건 이상 인입되는 고객 문의 및 사내 협업 메일을 일일이 열어 내용을 분석하고, 엑셀(스프레드시트)에 수동 분류 기록한 뒤, 담당자에게 메신저로 전파하는 전통적인 수작업 프로세스
* **기존 소요 시간 및 문제점:** 일일 평균 약 30~50분 소요, 업무 병목 현상 발생 및 긴급 건 지연 우려
* **자동화 도입 목적:** 수신된 이메일을 생성형 AI(OpenAI GPT-4o)가 실시간으로 독해하여 **핵심 3줄 요약 및 긴급도(High/Low) 분류**를 자동 수행하고, 긴급 건은 디스코드 채널로 즉시 푸시 알림을 발송하며, 전체 내역은 구글 시트에 자동으로 누적 적재하여 인적 리소스를 90% 이상 절감

---

## 2. 도구 선정 및 선정 이유
* **선정 도구:** **Make**
* **선정 이유:** 
  1. OpenAI 공식 모듈이 정교하게 지원되어 프롬프트 디자인 및 구조화된 JSON 데이터 출력을 안정적으로 유도할 수 있음.
  2. 무료 플랜 내에서도 시각적 Router(조건 분기)와 다단계 모듈 연결을 비용 제약 없이 자유롭게 테스트할 수 있음.
  3. Discord Webhook 연동이 단순하며, 데이터 패킷 흐름을 실시간 시각화하여 디버깅하기에 최적화되어 있음.

---

## 3. 워크플로우 아키텍처 및 상세 흐름 설명

```text
[Trigger: Gmail - Watch Emails]
               │
               ▼
[Action 1: OpenAI GPT-4o] (이메일 본문 분석, 핵심 3줄 요약 및 긴급도 분류)
               │
               ▼
       [Router (조건 분기)]
       ├── [Route A: 긴급도 High] ──> [Google Sheets 적재] ──> [Discord Webhook 긴급 알림 전송]
       └── [Route B: 긴급도 Low]  ──> [Google Sheets 적재] (일반 누적 보관)
---

### 상세 실행 단계별 로직
Trigger (Gmail - Watch Emails): 사용자의 메일박스에 새로운 인입 메일이 탐지되는 순간 웹훅 기반으로 실시간 트리거가 작동합니다.

Action 1 (OpenAI - Create a Completion): 수신된 메일의 제목과 본문 내용을 OpenAI 모델에 전달하여, 정해진 시스템 지침에 따라 [문의 유형 / 핵심 3줄 요약 / 긴급도 판별(High/Low)] 형태로 정형화된 텍스트 출력을 생성합니다.

Router & Filter: AI가 도출한 긴급도 값에 따라 데이터를 분기합니다.

Route A (High): 즉각적인 대응이 필요한 중요 문의 건만 필터링하여 통과시킵니다.

Route B (Low): 일반 참고용 및 단순 문의 건을 필터링하여 통과시킵니다.

Action 2 (Google Sheets - Add a Row): 분기 경로와 무관하게 모든 수신 메일의 처리 결과(수신시각, 발신자, AI 요약본, 긴급도)를 구글 스프레드시트에 안전하게 누적 기록합니다.

Action 3 (Discord Webhook): Route A(High) 조건을 충족한 긴급 건에 한하여, 디스코드 지정 채널에 실시간 텍스트 알림을 전송하여 담당자가 즉시 인지하고 후속 조치를 취할 수 있도록 지원합니다.

4. 예외 처리 및 에러 핸들링 (보너스 과제 구현)
실패 대응 전략: 외부 API(OpenAI 서버 응답 지연 또는 네트워크 단절 등)의 일시적 장애로 인해 워크플로우가 중단될 경우, 기본 에러 경로에 Error Handler 모듈을 배치하여 관리자에게 즉시 실패 원인과 타임스탬프가 포함된 비상 알림 이메일이 발송되도록 설계하였습니다. 이를 통해 시스템 중단 상황을 실시간으로 감지하고 데이터 무결성을 유지합니다.
