# 🤖 [프로젝트 2] AI 연동 자동 분류 및 디스코드 알림 파이프라인 상세 설계서 (상세 확장판)

## 1. 반복 업무 정의 및 자동화 도입 목적
* **대상 반복 업무:** 매일 수십 통씩 인입되는 고객 문의 및 사내 협업 메일을 담당자가 일일이 열어 내용을 독해하고, 엑셀 시트에 수동으로 분류·요약하여 기록한 뒤 메신저로 전파하는 비효율적 수작업 프로세스
* **기존 소요 시간 및 문제점:** 단순 반복 업무에 소요되는 시간적 손실(일일 평균 약 40분)과 휴먼 에러(중요 메일 누락 위험) 발생
* **자동화 도입 목적:** 생성형 AI(OpenAI GPT-4o)의 강력한 텍스트 독해 및 구조화 능력을 노코드 툴(Make)과 결합하여, 인입 메일의 핵심 3줄 요약 및 긴급도(High/Low) 판별을 완전 자동화하고 디스코드 채널로 실시간 알림 전파

--- 

## 2. 도구 선정 및 선정 이유
* **선정 도구:** **Make + OpenAI GPT-4o API**
* **선정 이유:** 
  1. Make의 공식 OpenAI 모듈을 통해 프롬프트와 응답 포맷(JSON 등)을 안정적으로 제어할 수 있음.
  2. 수신된 이메일 본문이라는 비정형 데이터를 AI가 정형화된 데이터로 정확히 변환해 주는 파이프라인 구축에 최적화됨.
  3. 에러 핸들링 및 조건 분기 모듈을 결합하여 시스템 안정성을 높일 수 있음.

## 3. 워크플로우 아키텍처 및 상세 흐름 설명
[Trigger: Gmail - Watch Emails]

│

▼

[Action 1: OpenAI GPT-4o] (이메일 본문 분석, 핵심 3줄 요약 및 긴급도 분류)

│

▼

[Router (조건 분기)]

├── [Route A: 긴급도 High] ──> [Google Sheets 적재] ──> [Discord Webhook 긴급 알림 전송]

└── [Route B: 긴급도 Low] ──> [Google Sheets 적재] (일반 누적 보관)

## 상세 실행 단계별 로직
**Trigger (Gmail - Watch Emails)**: 사용자의 메일박스에 새로운 인입 메일이 탐지되는 순간 웹훅 기반으로 실시간 트리거가 작동합니다.

**Action 1 (OpenAI - Create a Completion)**: 수신된 메일의 제목과 본문 내용을 OpenAI 모델에 전달하여, 정해진 시스템 지침에 따라 [문의 유형 / 핵심 3줄 요약 / 긴급도 판별(High/Low)] 형태로 정형화된 텍스트 출력을 생성합니다.

**Router & Filter**: AI가 도출한 긴급도 값에 따라 데이터를 분기합니다.

**Route A (High)**: 긴급도가 'High'로 판별된 중요 문의 건만 필터링하여 통과시킵니다.

**Route B (Low)**: 긴급도가 'Low'인 일반 참고용 및 단순 문의 건을 필터링합니다.

**Action 2 (Google Sheets - Add a Row)**: 분기 경로와 무관하게 모든 수신 메일의 처리 결과(수신시각, 발신자, AI 요약본, 긴급도)를 구글 스프레드시트에 안전하게 누적 기록합니다.

**Action 3 (Discord Webhook)**: Route A(High) Route A(High) 조건을 충족한 긴급 건에 한하여, 디스코드 지정 채널에 실시간 텍스트 알림을 전송하여 담당자가 즉시 인지하고 후속 조치를 취할 수 있도록 지원합니다.

## 4. 예외 처리 및 에러 핸들링 (보너스 과제 구현)
* **실패 대응 전략**: 외부 API(OpenAI 서버 응답 지연, 네트워크 단절 등)의 일시적 장애로 인해 워크플로우가 중단될 경우를 대비하여, 기본 에러 경로에 Error Handler 모듈을 배치하였습니다.

* **대체 경로 및 알림**: 에러 발생 시 시스템이 즉시 중단되는 대신, 관리자에게 실패 원인과 타임스탬프가 포함된 비상 알림 이메일이 발송되도록 설계하여 데이터 무결성과 시스템 모니터링 체계를 확보했습니다.
