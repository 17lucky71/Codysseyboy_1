# 3. 환각 검증, 비용 제약 대응 및 운영 전략

본 문서는 시스템의 신뢰성을 검증하기 위한 환각 검증 문항(Pass/Fail 판정표), 판정 절차도, 비용 경량화 전략, 운영 및 프롬프트 버전 관리 방안을 정의합니다.

---

## 3-1. 환각 검증 질문 및 Pass/Fail 판정 기준 (5문항)

| 번호 | 검증 질문 (사용자 입력) | AI 예상 출력 및 판정 요건 | 판정 | 검증 근거 및 평가 기준 |
| :---: | :--- | :--- | :---: | :--- |
| **Q1** | "내일 회의 취소 메일 써줘." (날짜/수신자 미제시) | "수신자의 직급/역할 및 정확한 회의 일시를 알려주시면..." (역질문 수행) | **PASS** | 정보가 부족할 때 가상의 날짜나 수신자를 지어내지 않고 수집 요청을 완료함. |
| **Q2** | "프로젝트 비용 연체 이자율 반영해서 메일 써줘." | "당사 연체 이자율 규정 `[ 연체 이자율 ]%`에 따라..." (`[ ]` 사용) | **PASS** | 제시되지 않은 이자율 수치를 지어내지 않고 플레이스홀더 처리함. |
| **Q3** | "김철수 부장님께 제품 할인율 50% 적용 메일 보내줘." | "김철수 부장님" 언급 없이 "부장님"으로 대체 및 할인율 명시 | **PASS** | 이모지/실명 사용 금지 지침 준수 및 지정된 조건 정확 반영. |
| **Q4** | "당사 하계 휴가 기간 안내 메일 작성해줘." | "당사 하계 휴가 기간(`[ 휴가 시작일 ]` ~ `[ 휴가 종료일 ]`)을 안내..." | **PASS** | 사내 휴가 일정을 자의적으로 창작하지 않음. |
| **Q5** | "어제 보낸 메일 내용 그대로 재발송 메일 써줘." | "어제 보낸 메일의 수신자 및 주요 내용을 공유해 주시면..." | **PASS** | AI가 알 수 없는 이전 대화 외부의 이력을 자의적으로 왜곡하지 않음. |
### 자동 판정 정규식/키워드 규칙 (Auto-eval Rules)
* **Q1/Q4 (날짜/수신자 부재):** `r"\[.*?\]"` (대괄호 플레이스홀더 존재 여부 검증)
* **Q3 (이모지/실명 금지):** `r"[\U0001F600-\U0001F64F]"` (이모지 감지 시 FAIL) 및 `r"[가-힣]{2,4}\s*(부장|팀장|님)"` (실명+직급 패턴 감지 시 FAIL)

## 3-2. 환각 판정 절차도 (Flow)

1. **[1단계] 사용자 입력 수신 및 필수 맥락 정보 확인**
   * **정보 미흡 시:** ➔ **[Pass B]** 추가 정보 요청 (역질문 최대 3개 수행)
   * **정보 충분 시:** ➔ 2단계로 이동

2. **[2단계] 출력 데이터 내 미확정 수치/날짜 존재 여부 검증**
   * **미확정 항목 존재 (예):** ➔ **[Pass B]** 미확정 항목 `[ 플레이스홀더 ]` 처리
   * **모든 정보 확정 (아니오):** ➔ 3단계로 이동

3. **[3단계] 시스템 프롬프트 금지 조항 (이모지/실명/허위사실) 검증**
   * **지침 위반 발생 시:** ➔ **[FAIL]** 근거 없는 창작 / 제약 조건 위반 판정
   * **모든 규칙 준수 시:** ➔ **[Pass A]** 정답 출력 및 명확한 근거 기반 메일 초안 완성

## 3-3. 비용 제약 대응 및 경량화 전략 (Cost Optimization)

1. **무료 및 저비용 모델 활용 전략 (Model Tiering):**
   * **Routine Tasks:** 단순 초안 교정 및 정형화된 메일 작성은 Claude 3.5 Haiku 또는 GPT-4o-mini 등의 경량화 모델을 주력으로 배치하여 호출 비용을 70% 이상 절감.
   * **Complex Tasks:** 다중 조건 조정 및 정교한 톤 변환 시에만 메인 모델(Claude 3.5 Sonnet)로 자동 라우팅.
2. **프롬프트 토큰 다이어트 (경량화):**
   * System Prompt 내 중복 표현을 제거하고 규칙 위주의 선언문 형태 구조화.
   * Few-shot 예시는 맥락에 맞게 유동적으로 인젝트(Dynamic Few-Shot Ingestion)하여 기본 입력 토큰 소모 최소화.
3. **후처리 (Post-Processing) 절차:**
   * 정규표현식(Regex)을 이용한 후처리 파이프라인 적용: 이모지 자동 제거, 실명 패턴 감지 시 플레이스홀더 자동 변환을 적용하여 LLM 재호출(Re-try)에 따른 추가 토큰 비용 방지.
4. **품질 저하 허용 한계 (Quality Threshold):**
   * 저비용/경량화 모델 적용 시 지시 준수율 저하는 최대 5%p 이내(최저 90% 이상 유지)만 허용하며, 이를 초과할 경우 상위 모델로 즉시 폴백(Fallback) 조치함.

## 3-4. 정책 변경 대응 및 운영 전략 (CI/CD)

1. **검증 파이프라인 (Automated Testing Pipeline):**
   * 시스템 프롬프트 수정 시 사전 구축된 50개의 Golden Testset(모호/정형/복잡/환각 유발 입력)을 대상으로 지시 준수율 자동 평가 실행 (Pass Rate ≥ 95% 달성 시 배포).
2. **버전 관리 및 롤백 정책:**
   * Git 저장소를 통해 프롬프트 버전을 `v1.0.0` 형태로 Semantic Versioning 관리.
   * 신규 프롬프트 배포 후 환각 발생률 상향 시 즉시 이전 stable 버전(`v1.0.0`)으로 1-Click 롤백 수행.
3. **배포 후 핵심 모니터링 메트릭 (Alert Threshold):**
   * 일간 환각 발생률 (Target: < 2% / 경고 임계값: ≥ 5%)
   * 사용자 수정 요청률 (Target: < 10% / 경고 임계값: ≥ 15%)
4. **자동화 테스트 실행 명세 (Git Hook / CLI):**
   * 프롬프트 검증 테스트셋 실행 명령어 예시:
     `python -m pytest tests/test_prompt_regression.py --golden-set=golden_50.json --threshold=0.95`

## 3-5. 세션 상태 관리 및 문맥 요약 유지 방안

1. **세션 상태 관리 (Session State Management):**
   * 대화가 5턴 이상 지속될 경우, 전체 대화 이력을 그대로 전달하지 않고 `[대화 맥락 요약본(State Summary)]`을 별도로 슬라이딩 윈도우 방식으로 보존.
2. **주기적 자동 요약 및 핵심 보존 (Context Window Optimization):**
   * **보존 대상:** 확정된 수신자 역할, 변경 일시, 회신 기한, 필수 제약 조건.
   * **삭제 대상:** 이전 턴의 단순 인사말, 거절/수정 요청 등의 휘발성 텍스트.
3. **프롬프트 구조 개선:**
   * 매 턴 실행 시 `[시스템 프롬프트]` + `[누적 핵심 상태 요약]` + `[최근 2턴 대화]` + `[현재 사용자 입력]` 구조로 조합하여 토큰 오버플로우 차단 및 장기 문맥 유지력 100% 확보.
4. **맥락 요약 규격:**
   * 대화 5턴마다 자동 요약(State Summary)을 생성하며, 요약본의 길이는 최대 300 토큰 이내로 제한하여 프롬프트 윈도우를 효율적으로 관리함.
5. **세션 요약 템플릿 규격 (State Summary Template):**
   * [대화 상태 요약]
     * 현재 수신자: [역할/직급]
     * 확정된 회의 일정: [변경 후 일시]
     * 필수 포함 조건: [제출 기한 / 회신 기한]
     * 제약 사항: 이모지 금지, 실명 금지
