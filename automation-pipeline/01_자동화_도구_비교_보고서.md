# 📊 [프로젝트 1] Make vs Zapier 자동화 도구 비교 보고서
 
## 📋 개요
 
"Google Forms 설문 응답 → 조건 분기(점수 기준) → Google Sheets 기록 + Discord 알림" 이라는 동일한 워크플로우를 **Make**와 **Zapier** 두 가지 노코드 자동화 도구에서 각각 실제로 구현하고 테스트하면서, 실무에서 체감한 차이점을 정리한 보고서입니다. 이론적인 비교가 아니라, 두 도구를 직접 사용하며 실제로 겪은 경험을 바탕으로 작성했습니다.

## 1. 조건 분기 기능 (Router vs Paths)
 
| 항목 | Make (Router) | Zapier (Paths by Zapier) |
|---|---|---|
| 무료 플랜에서 편집·테스트 | ✅ 가능 | ✅ 가능 |
| 무료 플랜에서 실제 활성화(Publish/ON) | ✅ 가능 | ❌ 불가능 (Professional 플랜 필요) |
| 조건식 표현 | "≥80"처럼 직관적으로 설정 가능 | "Greater than or equal to" 옵션이 바로 안 보여, "Greater than 79"로 우회 설정 |
| 분기 개수 제한 | 없음 (여러 Route 자유롭게 추가) | 무료 플랜에서도 여러 Path 추가는 가능하나 Publish가 막힘 |
 
가장 크게 체감한 차이는 **무료 플랜에서의 실사용 가능 여부**였습니다. Make는 Router가 들어간 시나리오도 무료 플랜에서 그대로 켜서(ON) 실시간 자동 실행이 가능했지만, Zapier는 Paths가 포함된 Zap을 Publish하려고 하면 "Upgrade to Pro to publish this Zap" 안내와 함께 막혔습니다. 이 때문에 Zapier 쪽은 에디터 안의 "Test step" 기능으로만 각 단계의 정상 동작을 검증할 수 있었고, 실제 폼 제출에 대한 실시간 자동 실행은 확인하지 못했습니다.

## 2. 트리거 방식과 실행 속도
 
| 항목 | Make | Zapier |
|---|---|---|
| Google Forms 트리거 방식 | 폴링(Polling) 방식, 스케줄 주기 설정 가능 (예: 15분) | 폴링 방식 |
| 실시간성 체감 | 스케줄을 켜두면 주기적으로 자동 감지, "Run once"로 즉시 수동 실행도 가능 | Publish 전에는 자동 실행 자체가 안 되어 즉시성 비교 자체가 불가능했음 |
| 백로그 처리 | 스케줄이 꺼져 있던 동안 쌓인 미처리 응답들을 재실행 시 한 번에 처리 (단, 회당 처리 개수에 제한이 있어 여러 번 실행 필요했음) | 해당 없음 (Publish 안 됨) |
 
Make에서는 스케줄 토글을 꺼두면 자동 실행이 멈추고, 다시 켜면 그동안 쌓인 응답을 처리한다는 점을 직접 실행하며 확인했습니다. 다만 한 번에 처리하는 응답 개수에 제한이 있어서, 백로그가 많이 쌓였을 때는 "Run once"를 여러 번 눌러야 전체 응답이 다 처리됐습니다.

## 3. 설정 난이도 및 UI/UX
 
| 항목 | Make | Zapier |
|---|---|---|
| 화면 구성 | 노드 기반 시각적 플로우 (한눈에 전체 구조 파악 용이) | 세로 리스트 기반 (Path 갈래는 좌우로 나뉘어 표시) |
| 데이터 매핑 | 이전 모듈 출력값을 클릭해 바로 삽입, 필드명이 명확 | "Insert Data" 패널에서 검색 후 선택, 필드 검색 편의성 좋음 |
| 계정 연동 | Google Forms 연동 후 다른 모듈에서도 계정 재사용 쉬움 | Google 계정은 자동 공유됐지만, Discord는 OAuth 방식으로 서버 단위 재승인 필요 |
| 예상치 못한 이슈 | Google Forms 응답 필드가 두 군데(Grade용/실제 응답용)에 있어 처음에 잘못된 경로로 매핑했던 적 있음 | Worksheet 드롭다운이 한 번씩 "No options are available"로 안 뜨는 경우가 있었으나 Refresh로 해결됨 |

## 4. 실제 테스트 결과 요약
 
| 항목 | Make | Zapier |
|---|---|---|
| 테스트 방식 | 실제 폼 제출 + 실시간 자동 실행(스케줄 ON) | 에디터 내 "Test step" (샘플/실제 데이터 기반) |
| 고득점(≥80) 경로 검증 | ✅ Google Sheets 기록 + Discord 알림 실시간 확인 (여러 차례) | ✅ Google Sheets 기록 + Discord 알림 확인 (수동 테스트) |
| 저득점(<80) 경로 검증 | ✅ Google Sheets에만 기록, Discord 알림 없음을 실시간으로 확인 (10점, 50점, 70점 등 다수) | ✅ 조건 통과 여부는 확인했으나, 실제 자동 실행으로는 검증하지 못함 |
| 에러 발생 여부 | 필드 매핑 오류 1건 (해결함), 이후 에러 없음 | 조건식 표현 우회 1건, Worksheet 로딩 지연 1건 (모두 해결함) |

## 🎯 결론
 
이번 프로젝트를 직접 구현하며 느낀 가장 큰 차이는, **조건 분기(Router/Paths) 자체의 기능 완성도보다도 "무료 플랜에서 실제로 켜서 쓸 수 있는지"** 였습니다. Make는 무료 플랜에서도 Router가 포함된 시나리오를 실시간으로 자동 실행할 수 있어, 개인 프로젝트나 소규모 자동화에 부담 없이 사용하기 좋았습니다. 반면 Zapier는 Paths 기능 자체는 잘 만들어져 있지만, 이를 실제로 활성화하려면 유료 플랜이 필요해서 무료 사용자 입장에서는 조건 분기가 들어간 자동화를 온전히 활용하기 어려웠습니다.
 
**실무 활용 관점 정리:**
- 예산이 없고 조건 분기가 필요한 자동화 → **Make** (무료 플랜으로도 충분히 실사용 가능)
- 이미 유료 플랜을 사용 중이거나, 앱 생태계(5,000개 이상 연동)가 중요한 경우 → **Zapier**
