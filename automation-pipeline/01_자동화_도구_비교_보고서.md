# 📊 [프로젝트 1] 노코드 자동화 도구 비교 분석 보고서

## 1. 개요 및 워크플로우 비즈니스 목적
* **배경 및 선정 이유:** 기업의 고객 지원 팀이나 인사(HR) 부서에서는 매일 수많은 설문 및 문의를 접수하고, 이에 대한 우선순위를 판별하여 담당 부서에 전파하는 반복 업무가 발생합니다.
* **워크플로우 시나리오:**
  * Trigger: Google Forms를 통한 고객 설문/문의 접수
  * Logic (조건 분기): 입력된 점수 또는 키워드에 따라 우선순위 판별 (우수/긴급 vs 일반)
  * Action 1 (Data Repository): 구글 스프레드시트에 모든 데이터를 누적 적재하여 데이터베이스화
  * Action 2 (Alert System): 긴급 건에 한하여 디스코드 또는 슬랙 채널로 실시간 푸시 알림 발송

## 2. 도구별 워크플로우 아키텍처 설계

### 🟣 Make (Integromat) - 구현 상세
* **Trigger 구성:** Google Forms - Watch Responses 모듈을 배치하여, 새로운 설문 응답이 제출되는 즉시 웹훅(Webhook)을 통해 데이터 패킷이 실시간으로 수신되도록 연동합니다.
* **Router 구성:** 하나의 중앙 Router 모듈을 배치하고 두 개의 경로(Route)로 분기합니다.
  * **Route A (High Priority):** 필터 조건에 Score >= 80 또는 Keyword = '긴급'을 설정하여 중요 데이터만 통과시킵니다.
  * **Route B (Normal Priority):** 그 외 일반적인 데이터를 처리하는 기본 경로로 지정합니다.
* **Action 모듈 연결:** 각 경로 끝에 Google Sheets - Add a Row를 연결하여 시트에 기록하고, Route A에는 추가로 Discord - Send a Message 모듈을 연결해 즉각적인 알림을 실행합니다.

### 🟠 Zapier 구현 상세
* **Trigger 구성:** Google Forms - New Response in Spreadsheet 모듈을 사용하여, 설문 제출 시 자동으로 연동된 구글 스프레드시트의 새 행 추가 이벤트를 폴링(Polling) 방식으로 감지합니다.
* **Paths (조건 분기 기능):** 수직 구조 하위의 분기 경로 지정
  * **Path A:** Score Greater than or equal to 80 (고득점/우선 처리 로직)
  * **Path B:** Score Less than 80 (일반 처리 로직)
* **Action 1 (Data Repository):** Google Sheets - *Create Spreadsheet Row*
* **Action 2 (Alert System):** Discord / Slack - *Send Channel Message*

## 3. 심층 비교 분석 (5가지 핵심 항목)

| 비교 항목 | Make (Integromat) | Zapier |
| :--- | :--- | :--- |
| **1. UI/UX 및 아키텍처 형태** | **2차원 비주얼 캔버스(Node):** 무한 캔버스 위에서 모듈을 자유롭게 배치하고 화살표로 연결하여, 복잡한 병렬 처리 및 다중 분기를 직관적으로 조망 가능 | **수직형 선형 리스트(Step):** 위에서 아래로 순차적으로 흐르는 깔끔한 구조이나, 분기가 많아지면 스크롤이 길어지고 전체 구조 파악이 다소 불편함 |
| **2. 설정 난이도 및 학습 곡선** | **중~상:** 데이터 패킷(Data Bundle)과 JSON 구조 개념에 대한 이해가 초기 단계에 요구되나, 숙달 시 무한한 제어력 확보 가능 | **하:** 친절한 가이드와 강력한 온보딩 프로세스로 인해 비개발 직군도 수 분 내에 기초적인 플로우 구축 가능 |
| **3. 연동 서비스 범위 및 확장성** | **광범위함 (1,500+개):** 세부 API 파라미터 직접 제어 및 HTTP 모듈을 통한 커스텀 웹훅(Webhook) 연동 시 압도적인 유연성 제공 | **최상 (5,000+개):** 대중적인 거의 모든 글로벌 SaaS 솔루션과 기본 연동되며, 복잡한 인증 절차를 마법사 형태로 간소화 |
| **4. 무료 플랜 정책 (Free Tier)** | **월 1,000 Operations / 기능 제한 없음:** 무료 플랜에서도 복잡한 Router 및 다단계 조건 분기, 반복문을 제한 없이 테스트 가능 | **월 100 Tasks / 2-Step 제한:** 2단계를 초과하거나 조건 분기(Paths) 기능을 활용하려면 무조건 유료 플랜(Pro 이상)으로 업그레이드 필요 |
| **5. 실행 로그(History) 및 디버깅** | **실시간 데이터 패킷 시각화:** 모듈 간 오고 가는 데이터 값을 실시간 애니메이션과 상세 로그로 즉시 검증 가능 | **Task History 리스트:** 실행 성공/실패 여부 및 단순 텍스트 로그 위주로 제공되어 상세한 데이터 변환 과정을 추적하기에는 다소 제한적 |

## 4. 장단점 정리 및 실무 도입 의견

### 🟣 Make
* **장점:** 무료 플랜의 가용 범위가 매우 넓고, 비주얼 노드 구조 덕분에 복잡한 비즈니스 로직(다중 분기, 에러 핸들링 등)을 추가 비용 없이 완벽하게 구현할 수 있습니다.
* **단점:** 초보자에게는 데이터 매핑 인터페이스와 모듈 간 연결 방식이 다소 복잡하게 느껴질 수 있습니다.
* **적합한 상황:** 복잡한 조건 분기가 수반되는 업무 프로세스, API 커스텀 제어가 필요하거나 비용 효율성(ROI)을 최우선으로 고려하는 프로젝트.

### 🟠 Zapier
* **장점:** 압도적인 앱 생태계와 직관적인 UX를 갖추어 러닝 커브가 거의 없고 누구나 쉽고 빠르게 자동화를 시작할 수 있습니다.
* **단점:** 무료 플랜의 제약(Tasks 소모 속도, 고급 기능 유료화)이 엄격하여 본격적인 업무 자동화 구축 시 비용 부담이 가중됩니다.
* **적합한 상황:** 단순 선형 구조(A ➡️ B ➡️ C)의 빠른 업무 자동화가 필요하거나, 비개발 직군 중심의 팀에서 가볍게 도입하는 경우.
